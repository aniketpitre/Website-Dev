# JWT direct linking troubleshooting

This guide contains common issues and error codes you may encounter when implementing JWT direct linking. This document is organized into two sections:

- [Common issues](#common-issues)
- [Error codes](#errors)
  - [HTTP request errors](#http-errors)
  - [JWT header/payload errors](#jwt-errors)
  - [Account-related errors](#account-errors)

## Common issues

<dl><dt>App refused to connect</dt><dd>If you receive this error when rendering the connection <code>&lt;iframe&gt;</code>, it is usually because your browser security settings do not allow third-party cookies. Configure your browser to enable cookie access in a third-party context.</dd><dd><strong>Google Chrome:</strong> Enable all cookies. Google Chrome blocks third-party cookies in Incognito mode by default. Enable third-party cookies in Incognito mode by going to <strong>Settings</strong> &gt; <strong>Privacy and security</strong> &gt; <strong>General settings</strong> and select <strong>Allow all cookies</strong>.<br><img alt="Chrome cookies" src="/assets/google-cookies.Dn1QPl_W.png" data-no-zoom=""><br></dd><dd><strong>Apple Safari:</strong> Disable <strong>prevent cross-site tracking</strong> in <strong>Preferences &gt; Privacy.</strong></dd><dt>Browser compatibility</dt><dd>Workato supports all leading browsers, including Chrome, Firefox, Edge, and Safari. Workato does not support Internet Explorer. If you currently use Internet Explorer, switch to Microsoft Edge to test Embedded functionality.</dd><dt>Embedded customers redirected to Workato login (Firefox)</dt><dd>Embedded customers may be redirected to the Workato login page when attempting to establish a connection. Embedded customers should add your origin URL(s) to Firefox's Enhanced Tracking Protection exceptions through <strong>Settings &gt; Privacy &amp; Security &gt; Enhanced Tracking Protection &gt; Manage Exceptions</strong> to resolve this.<br><img alt="Firefox Manage Exceptions dialog for adding allowed sites" src="/assets/firefox-manage-exceptions.DsitWh-v.png"><br>When you configure multiple origin URLs (such as regional domains), Embedded customers must add exceptions for each domain. Embedded customers can also switch to Chrome or another supported browser.</dd><dt>Workato iframe not receiving connection events</dt><dd>Workato uses the <a href="https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage">PostMessage API</a> to send event information from the connection <code>iframe</code> to the partner application. These messages include connection status changes, height changes, error messages and more. The <code>iframe</code>'s origin URL must be allowlisted in Workato. Contact your Workato Success Representative to configure the backend environment if you cannot receive these messages.</dd></dl>

> **MULTIPLE ORIGINS**
> 
> Some use cases require you to receive PostMessages in multiple origins, including embedding the Connection Widget in multiple customer workspaces. In this scenario, your Workato Customer Success Representative cannot configure the URL for you. Update the Embedding Origin configuration in each individual customer workspace by navigating to **Admin > Manage Customers > Choose Customer > Settings > Embedding Origin.** Alternatively, update the origin URL by calling our [update customer API.](/en/oem/oem-api/managed-users#update-customer-account)

## Error codes

You may encounter the following errors when implementing JWT direct linking. We organized this list by error category.

- [HTTP request errors](#http-errors)
- [JWT header/payload errors](#jwt-errors)
- [Account-related errors](#account-errors)

### HTTP request errors

<dl><dt>http_request_invalid</dt><dd>Requests sent to our servers must meet the following conditions: it is a valid HTTP request, it is in HTML format, and it is not in XHR format. Verify that the request meets the specified conditions to resolve this error.</dd><dt>path_invalid</dt><dd>The path provided must be valid and secured with HTTPS. To resolve this error, verify that the URL/path is valid and begins with <code>https://</code>.</dd></dl>

### JWT header/payload errors

<dl><dt>alg_invalid</dt><dd>The signing algorithm used in the header of the JWT is not <code>RS256</code>. To resolve this error, verify that the <code>alg</code> claim in the header of the JWT has the value RS256.</dd><dt>iat_invalid</dt><dd>The <code>iat</code> (issued at) claim in the payload of the JWT is not an integer. To resolve this error, verify that the <code>iat</code> claim in the payload is an integer.</dd><dt>iat_missing</dt><dd>The <code>iat</code> (issued at) code in the payload of the JWT is not present. Verify that the <code>iat</code> claim in the payload is present to resolve this error.</dd><dt>jti_invalid</dt><dd>The <code>jti</code> (JWT ID) claim is not a string or an integer. To resolve this error, verify that the <code>jti</code> claim in the payload is either a string or an integer.</dd><dt>jti_missing</dt><dd>The <code>jti</code> (JWT ID) claim is missing from the payload of the JWT. To resolve this error, verify that the <code>jti</code> is present.</dd><dt>jti_reused</dt><dd>The <code>jti</code> (JWT ID) claim in the JWT payload has been used more than one time to render an iframe. The <code>jti</code> claim is a unique identifier that allows a JWT to be used one time. To resolve this error, use a globally unique <code>jti</code> claim value when generating the JWT token.</dd><dt>token_expired</dt><dd>The generated JWT token is valid for 30 seconds. Verify the token generates in real-time and that the <code>iat</code> claim in the payload has a value of +/- 30 secs from the current time to resolve this error.</dd><dt>token_invalid</dt><dd>This error suggests that one of the JWT components is missing or incorrectly formatted. In its compact form, a correctly structured JWT contains a header, payload, and signature in the following format: <code>header.payload.signature</code>. To resolve this error, decode the JWT and verify that the header and payload are properly formatted.</dd><dt>token_missing</dt><dd>The JWT is missing. Verify that the JWT is present in the request to resolve this error.</dd><dt>token_signature_invalid</dt><dd>The signature (private key) used to sign the JWT is invalid. To resolve this error, decode the JWT and verify that the signature used to sign the JWT is correctly configured.</dd></dl>

### Account-related errors

<dl><dt>member_invalid</dt><dd>This error occurs when the user attempting to access the workspace is not a valid workspace member. Verify that the user trying to access Workato has been added to the customer team correctly.</dd><dt>member_unconfirmed</dt><dd>The workspace member's account is not confirmed. Confirm the customer workspace member's email to resolve this error. If this is not possible, contact your Workato Success Representative for assistance.</dd><dt>team_direct_team_link_disabled</dt><dd>This error occurs when the customer uses an old account to test Embedded, meaning that the account existed before the OEM was configured. The OEM configuration doesn’t apply to accounts created before the change. To resolve this error, create a new customer. If the error persists in the new account, contact your Workato Success Representative for assistance.</dd><dt>team_missing</dt><dd>This error occurs when a user tries to access Workato and does not belong to a customer team. Verify that the user trying to access Workato has been added to the customer team correctly.</dd><dt>team_not_allowed</dt><dd>This error occurs when the admin account ID is used while generating the JWT. Embedded does not let an <code>iframe</code> render if you use your admin account ID while generating the JWT. To resolve this, change the ID of the account to a customer ID. If the error persists, contact your Workato Representative for assistance.</dd><dt>team_saml_required</dt><dd>This error occurs when a user tries to access a team that has SAML SSO enabled. The user must enable SAML SSO and log in through the SAML IdP. Contact a team admin to ensure this user is SAML SSO enabled and that they have access to log in through the SAML IdP.</dd><dt>team_unconfirmed</dt><dd>The team account is not confirmed. Confirm the customer team’s email to resolve this error. If this is not possible, contact your Workato Success Representative for assistance.</dd><dt>vendor_admin_missing</dt><dd>The Embedded partner's account is not properly configured. To resolve this error, contact your Workato Success Representative for assistance.</dd><dt>vendor_direct_team_link_disabled</dt><dd>The Embedded partner's account is not properly configured. Contact your Workato representative for assistance.</dd><dt>vendor_key_missing</dt><dd>This error occurs when the Embedded partner's account is not assigned a unique key. If the error persists, contact your Workato representative for assistance.</dd><dt>vendor_missing</dt><dd>This error occurs when the Embedded Vendor ID used to generate the JWT token is incorrect, or the public key does not match the private key used to sign the JWT token. Verify that the API and public keys match Workato’s backend configs. If the error persists, contact your Workato Success Representative for assistance.</dd><dt>X-frame-options: same_origin</dt><dd>Embedded does not let an iFrame render if the user ID passed into the JWT references the Embedded admin user (owner of the admin account) or an Embedded customer manager (from within the admin account). If you pass a customer workspace ID into the payload of the JWT, verify that the customer ID was created in the customer workspace referenced. If the error persists while using the correct customer ID, clear the browser cache/cookies and try again.</dd></dl>
